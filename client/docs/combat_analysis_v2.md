# Анализ боевой системы v2 — Глубина, фидбек, баланс

Дополнение к `combat_system_improvements.md`. Фокус на архитектуре боя, тактической глубине, PvP/PvE асимметрии и проблемах геймдизайна.

---

## 1. Оружие игрока — пушка и лазер

### 1.1. Cannon vs Laser — разделение ролей

Игрок использует оба типа одновременно (см. `firePlayerWeapon`: `if (p.hasCannon)... if (p.hasLaser)...`). Разница: laser `×0.90` по щиту, `×1.30` по корпусу.

**Проблема:** Нет ситуации, когда игрок сознательно выбирает, чем стрелять. Оба типа всегда летят в цель одновременно. Разница в множителях — не тактический выбор, а скрытая математика.

**Предложение (лёгкое):** Разделить кнопки стрельбы — пушки по ЛКМ, лазеры по ПКМ. Это добавляет микро-решение "чем бить сейчас" без добавления нового оружия.

## 2. Система попаданий — математический оверхед

### 2.1. Цепочка множителей урона

Последовательность расчёта `_fireCannon`:

```
урон = BASE_damage × skillMult × ammoMult × perkMult × (isCrit ? critMult : 1)
       × {accuracy check → промах}
       × {penetration → split shield/hull}
       × {damageResistMod на цели}
       × {shieldMult, hullMult на цели}
       × {evasion check → додж}
       × {kineticAbsorb → абсорб}
       × {adaptiveResist → снижение повторного урона}
       × {splinterRes → снижение AoE урона}
       × {lastStand → снижение на низком HP}
       × {reflectChance → отражение}
       × {reactivePct → отражение}
```

**Проблема:** 14+ ступеней модификации урона для одного выстрела. Невозможно предсказать, сколько урона пройдёт. Для игрока это "black box" — он не понимает, почему его выстрел нанёс 150, а не 300.

**Рекомендация:** Упростить до 3-4 слоёв:
1. Базовый урон × множитель способности (скилл/крит)
2. Проникновение (щит/корпус)
3. Сопротивление цели (единый `damageTakenMult`)
4. Уклонение (один бросок, не два — сейчас `evasion + movEvasion`)

### 2.2. Проблема предсказуемости PvP

Игрок не видит статов противника — не знает, есть ли у него `kineticAbsorb`, `adaptiveResist`, `lastStand`. Попадание может быть полностью обнулено случайным перком, о котором игрок даже не подозревает.

## 3. AI мобов — богатство, скрытое от игрока

### 3.1. Большое разнообразие AI-классов

Мобы имеют 10+ AI-классов: `gunner`, `dasher`, `berserker`, `shielder`, `cloaker`, `swarmDrone`, `flanker`, `bomb`, `directedMine`, `stunMine`, `minelayer`.

**Проблема:** Игрок не видит разницы между ними:
- Все мобы выглядят как спрайты одного стиля (корабли/дроны)
- Нет индикатора AI-класса в HUD цели
- Нет подсказки "этот моб телепортируется за спину" или "этот ставит мины"

**Рекомендация:**
- Добавить иконку AI-класса рядом с HP-баром цели (например, ⚡ для dasher, 🛡 для shielder, 👻 для cloaker)
- Подсветка класса при наведении/TAB
- Полоска-предупреждение перед минным залпом

### 3.2. Separation уже реализован, но есть узкие места

`applySeparation` из Mob.js работает для всех мобов. Однако при 15+ мобах в данже (DUNGEON_MOB_GROWTH до ×1.5) расчёт O(n²) может тормозить.

## 4. PvP архитектура — гибридная модель

### 4.1. Сервер-авторитетный PvP

PvP устроен грамотно: клиент НЕ считает урон сам, а отправляет `fireClaim` на сервер, который роллит крит, сверяет с лоаудаут-снэпшотом и возвращает `pvp_hit_result`.

**Проблема:** `_fireLaser` отправляет fireClaim с `targetHull/targetShield` (текущие HP цели на клиенте). Сервер сверяет их со своими — при латенси >100ms данные могут расходиться, что ведёт к rejection выстрелов или неверному учёту.

**Рекомендация:** Убрать `targetHull/targetShield` из fireClaim — сервер сам знает актуальное состояние цели через свою модель.

### 4.2. Отсутствие kill-cam / replay

В PvP убийство выглядит как:
1. Цель исчезает
2. Взрыв спрайта
3. Надпись `КРИТ!` (если крит)

Нет понимания: "откуда прилетело?", "сколько HP было до удара?", "какой скилл/перк сработал?".

### 4.3. Лоадаут-снэпшот — жёсткая фиксация

```js
// GameScene._pvpLoadoutSnapshot — фиксирует статы при входе в PvP-комнату
```

**Проблема:** Если игрок сменил модуль/скилл будучи в PvP-секторе, сервер всё равно считает по старому снэпшоту. Пользователь не понимает, почему обновлённые статы не применяются (нет UI-уведомления "смена экипировки вступит в силу после выхода из PvP-зоны").

## 5. Тактильная обратная связь (Juice)

### 5.1. Хорошо: что уже есть

- `muzzleFlash` — вспышка при выстреле
- `hitFlash` — белая вспышка на цели (добавлено недавно)
- `showDamage` — плавающие цифры урона
- `explosion` — взрыв при уничтожении
- `_cannonMuzzleFx` — дульный эффект

### 5.2. Проблемы

- **Нет звуковой разницы** между попаданием по щиту и по корпусу (разные звуковые файлы были бы ценны)
- **Плавающие цифры** не показывают penetration — игрок не знает, сколько урона ушло в щит, сколько в корпус
- **Нет индикации промаха моба** — пули мобов, уходящие в пустоту, выглядят как попадания
- **Нет вибрации/шейка камеры** при получении урона от босса — потеря immersivity

### 5.3. Отдача оружия не реализована

Из первого документа: сдвиг спрайта на 2-4px при выстреле + возврат tween. Это отсутствует сейчас. Стоимость реализации минимальная, влияние на feel — значительное.

## 6. Таргетинг и переключение целей

### 6.1. Переключение целей (TAB)

TAB переключает между всеми живыми мобами. В плотных роях (10+ мобов) TAB может перебирать десяток целей, включая тех, кто за пределами экрана — дезориентирует.

**Рекомендация:** TAB должен циклировать только по мобам в пределах дальности стрельбы и видимости камеры.

## 7. Расходники и бустеры

### 7.1. Бустеры — отсутствие тактического выбора

Бустеры (Damage +10%, Hull +20%, Shield +20%, XP +25%) — shop-предметы с таймером. Висят в HUD-виджете, включил и забыл.

**Проблема:** Нет тактического выбора — бустеры не ситуационные, а чистый стат-буст. Нельзя выбрать "сейчас мне нужно больше щита, а не урона" в моменте.

**Предложение:** Сделать бустеры одноразовыми на короткое окно (30-60 секунд) с КД после использования. Тогда игрок решает: "сейчас я вхожу в бой с боссом — включаю бустер урона" vs "меня преследуют — включаю щит".

## 8. Специфические проблемы PvE

### 8.1. Масштабирование мобов — линейное и предсказуемое

```js
function scaleStat(base, level) { return Math.round(base * (1 + 0.5 * (level - 1))); }
```

Все статы мобов растут линейно: +50% за уровень. Это означает, что разница между ур.10 и ур.20 мобом — ровно ×5.5 по всем статам.

**Проблема:** Нет вариативности — все мобы одного уровня имеют одинаковый множитель. Нет "сильных" и "слабых" мобов одного уровня, кроме базовых значений шаблона.

### 8.2. Босс-фазы: ярость и телеграф

Реализованы:
- Enrage при 40% HP (×1.6 fire rate, ×1.35 speed, красный тинт)
- AoE телеграф (кольцо → детонация)
- Фазы бронепоезда (50%/20% HP → спавн дронов)

**Проблема:** Телеграф AoE уже есть, но во всём проекте только ОДИН тип телеграфируемой атаки (AoE-кольцо). Добавление 2-3 паттернов (конус перед боссом, луч по прямой, "здесь будут мины через 2 сек") разнообразило бы бой.

## 9. Миссинг-фичи

### 9.1. Environmental hazards
- Астероидные поля, замедляющие/повреждающие корабль
- Туманности, снижающие видимость/точность
- Гравитационные колодцы, искажающие траекторию снарядов

### 9.2. Комбо-метка (Weak Spot)
После попадания лазером по открытому корпусу (щит <10%) ставить на цель дебафф "+15% урона от следующей плазмы на 3 секунды". Это создало бы микро-ритм "лазер → пушка → лазер → пушка" вместо "просто жмём ЛКМ".

### 9.3. Корабельные способности — только активные скиллы

У каждого корабля есть 1 активная способность (Recall, Afterburner, Dome, Cloak и т.д.). Они интересны, но пассивные способности кораблей (`passives`) очень скудные.

**Рекомендация:** Добавить 1 passive слот на корабль (выбирается в гараже), который меняет манеру боя:
- "Overdrive: +15% скорострельность, -10% к точности"
- "Fortress: +10% к сопротивлению, -15% к скорости"
- "Sniper: +20% дальность, +10% крит, -20% скорострельность"

## 10. Дополнительные идеи

### 10.1. Death Recap

После смерти игрок видит модалку:
- **Кто убил:** название моба/игрока
- **Сколько урона прилетело за последние 3 секунды:** разбивка по типам (плазма/лазер/кислота и т.д.)
- **Расстояние до атакующего в момент смерти**
- **Были ли активны: щит-дрон? баффы? дебаффы?**

Сейчас после смерти в PvP игрок не знает, что произошло. Большой взрыв, экран смерти — и всё. В PvE: умер в данже — надо гадать, отчего.

**Реализация:** `DeathRecap` — массив лога урона за последние N секунд, показывается в `_showRepairDialog` или отдельной модалке.

### 10.2. Weapon Heat — контроль темпа стрельбы

**Идея:** У каждых орудий есть шкала нагрева. При непрерывной стрельбе накопленный жар снижает точность (спред болтов растёт). Если превысить 100% — оружие "заклинивает" на 3 секунды с тултипом "ПЕРЕГРЕВ".

- Игрок контролирует темп: короткие очереди vs длинная очередь с риском перегрева
- Винтажный sci-fi стиль (звук нарастающего жужжания)
- Не требует нового оружия или изменения баланса — только визуальный/звуковой слой поверх существующего `fireCooldown`

**Реализация:** Добавить `weaponHeat` (0–100) в Player, инкремент при каждом выстреле, декремент со временем. При heat > 80 — `cannonAccuracy` временно снижается. При heat >= 100 — fire блокируется на 3 секунды.

### 10.3. Collision / Ramming Damage

**Идея:** При столкновении корабля игрока с мобом на высокой относительной скорости нанести обоим урон пропорционально скорости.

- Мотивирует манёвры: "протаранить слабого моба" vs "уклониться от сильного"
- Добавляет слою физики ещё один риск-награда элемент
- У мобов-роя (swarm) это опасно — они и так налетают толпой

**Гейт:** Минимальная скорость (например, > 200 px/s). Урон: `(relSpeed / 1000) * (massPlayer / massMob)`.

### 10.4. Визуал регена щита

**Идея:** Когда у игрока проходит `shieldRegenDelaySec` (6 секунд после последнего урона) и щит начинает регенерировать — добавить визуальный эффект:
- Тонкая циановая аура вокруг спрайта корабля (glow / пульсация)
- Нарастающий звук "зарядки"

Сейчас игрок не знает, когда начнётся реген щита — смотрит на полоску в HUD. Визуал на спрайте даёт ситуационную осведомлённость без отвлечения на UI.

### 10.5. Звуковая дифференциация shield-hit vs hull-hit

Сейчас звук попадания по врагу один и тот же (`sfx_cannon_hit`). Игрок не слышит разницы между:
- "попал по щиту" (высокий тон, электрический треск)
- "пробил корпус" (низкий гулкий удар)

Два дополнительных звуковых файла + минимальная логика (`shieldHit > 0` vs `hullHit > 0`) — кардинально улучшают тактильную обратную связь.

## 11. Сводка предложений по приоритету

| Приоритет | Изменение | Влияние на игровой опыт |
|---|---|---|
| **Высокий** | Показать AI-класс моба (иконка в HUD) | Игрок понимает, чего ожидать от врага |
| **Высокий** | Разделить ЛКМ/ПКМ на пушку и лазер | Микро-решения в бою без нового оружия |
| **Высокий** | Death recap: что убило, сколько, откуда | Учиться на ошибках, а не гадать |
| **Средний** | Отдача спрайта + микро-шейк камеры | Immersivity, "вес" оружия |
| **Средний** | Звуковая разница shield-hit vs hull-hit | Тактильный фидбек |
| **Средний** | Плавающие цифры: показывать щит/корпус отдельно | Прозрачность боя |
| **Средний** | TAB-циклирование только по видимым целям | Удобство таргетинга |
| **Средний** | Индикатор перегрева оружия (винтажный стиль) | Контроль темпа, anti-spam |
| **Низкий** | Kill-feed в PvP | Социальный фидбек |
| **Низкий** | Прожимной урон (ramming) | Дополнительный риск-награда манёвр |
| **Низкий** | Подсветка регена щита (glow на спрайте игрока) | Понятный визуал "щит в норме" |
