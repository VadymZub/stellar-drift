# Roadmap / Backlog

Пункты, обсуждённые в рамках анализа боевой системы (`combat_system_improvements.md`,
`combat_analysis_v2.md`), которые решено НЕ делать сейчас, а вернуться позже.

## 1. Окно объяснения формулы урона (на доработку)

Сейчас урон считается через 14+ последовательных модификаторов (скилл-множитель,
ammo-множитель, перк-множитель, крит, пробитие щит/корпус, сопротивления цели,
уклонение, kinetic absorb, adaptive resist, splinter resistance, last stand,
reflect/reactive — см. `_fireCannon`/`_fireLaser` в `GameScene.js` и `takeDamage()` в
`Player.js`/`Mob.js`). Игрок не видит разбивку — только итоговое число.

**Идея:** отдельное окно/панель (из Гаража или из боевого лога) с построчной разбивкой
последнего выстрела/попадания: базовый урон → что добавили скиллы/перки → крит →
пробитие → сопротивление цели → итог. Не меняет саму формулу — только прозрачность для
игрока.

**Статус:** не реализовано, ждёт отдельной проработки UI (куда встроить: Гараж? боевой
лог? тултип по выстрелу?).

## 2. Новые боевые фичи (обсудить отдельно, не багфиксы)

Всё ниже — новый контент/механики с нуля, не доработка существующего:

- **Weapon Heat** — шкала перегрева оружия при непрерывной стрельбе, снижает точность
  выше 80%, блокирует стрельбу на 3с при 100%. Чисто визуально-звуковой слой поверх
  существующего `fireCooldown`, баланс не трогает.
- **Ramming / таранный урон** — столкновение с мобом на высокой относительной скорости
  наносит урон обоим сторонам пропорционально скорости.
- **Environmental hazards** — астероидные поля (замедление/урон), туманности
  (видимость/точность), гравитационные колодцы (искажение траектории снарядов).
- **PvP Kill-feed** — лента убийств в углу HUD (`[PlayerA] 💥 [PlayerB]`).
- **Passive-слот кораблей** — 1 пассивный слот на корабль (выбирается в Гараже) поверх
  существующей активной способности: например "Overdrive" (+15% скорострельность,
  -10% точность), "Fortress" (+10% сопротивление, -15% скорость), "Sniper" (+20%
  дальность, +10% крит, -20% скорострельность).
- **Комбо-метка "Weak Spot"** — лазер по открытому корпусу (щит <10%) ставит дебафф
  "+15% урона от следующей плазмы" на 3с.

**Статус:** записано, не реализовано. Обсудить приоритет и объём каждого пункта отдельно
перед стартом работы.

## 3. Argus Control — перенести спавн/хил/force-ability на сервер

Сейчас `admin.html` → "Argus Control" управляет боссом через `BroadcastChannel`
(`ArgusController.js`) — это чисто локальный межвкладочный канал ОДНОГО браузера, не
сетевой. Сама логика спавна/фаз/self-heal/force-ability живёт в клиентском коде
(`ArgusController.js`), и `admin.html` может её только попросить исполниться в уже
открытой вкладке с игрой ("живая марионетка" в том же браузере, залогиненная в нужный
сектор) — без неё команда никуда не уходит ("Игра не подключена. Запустите игру в
соседней вкладке браузера."). После спавна урон/абилки уже нормально идут через сервер
(`pvpMobId`, как у обычных мобов) — ограничение именно в ТРИГГЕРЕ действия, не в
дальнейшей синхронизации с другими игроками.

**Запрос:** "зачем админ панели окрытая игра? должно работать с сервером напрямую" —
согласны, это архитектурно правильно, но не мелкий фикс.

**Что нужно:** портировать spawn/despawn/heal/force-ability/фазовую и self-heal логику
Аргуса на Python (`ServerMob`, по образцу остальных server-authoritative мобов — см.
[[server_authoritative_mobs_status]]), чтобы `admin.html` дёргала обычный REST-эндпоинт
(`POST /admin/argus/spawn` и т.п.) без необходимости держать открытую вкладку-марионетку.

**Статус:** не реализовано, отложено — "записать в roadmap, не сегодня".

## 5. Кнопка "Выход" (logout) — ЗАПЛАНИРОВАНО, ждёт подтверждения фикса регистрации

Раз мультиаккаунт на одну почту разрешён (см. диалог "разреши несколько аков на 1
почту"), игрокам нужен быстрый способ выйти и зайти под другим аккаунтом, не закрывая
приложение целиком. **Ждёт**: подтверждения, что фикс регистрации в приложении (CSP,
`v1.1.375`) реально работает — начинать делать logout только после этого.

**Точные требования (из диалога):**

1. Новая кнопка на HUD-панели соц-кнопок (`HudScene.js` `_buildHudSocialButtons()`
   `BTN_DEFS`) — САМАЯ ПРАВАЯ, после существующей `set` (⚙ НАСТРОЙКИ), которая сейчас
   крайняя.
2. По клику — 5-секундный отсчёт (countdown UI, по аналогии с существующими
   countdown/warning-оверлеями, напр. `_showJumpDangerWarning` в GameScene.js).
   - Если корабль **сдвинулся** за время отсчёта (сравнить x/y с моментом старта) —
     отменить выход.
   - Если корабль **атакован** (свежий `player.lastDamageAt`, тот же паттерн, что
     `recentlyHit` в Mob.js — окно ~несколько секунд) — отменить выход И написать в
     лог "выход под атакой невозможен".
3. Данж/босс-карта (`SECTORS[key].isDungeon`/боссовые сектора) — выход РАЗРЕШЁН, но
   ПЕРЕД стартом отсчёта показать предупреждение: "при повторном входе вы будете
   перемещены на ближайшую домашнюю базу — продолжить?" (да/нет). Это не техническое
   ограничение, а честное предупреждение — прогресс инстанса всё равно не резюмируется
   после выхода из игры.
4. По истечении отсчёта без отмены — реальный logout: `clearSession()` (см. api.js),
   остановить игровые сцены, перейти на `LoginScene` (страница авторизации).

**Что переиспользовать:** `_resolveStartSector()` в LoginScene.js уже вычисляет
"домашний сектор корпорации" как фолбэк для недопустимых секторов при входе (сейчас
жёстко исключает только `shadow_arena`/`R-1-boss` — при реализации стоит проверить,
нужно ли обобщить это на ЛЮБОЙ `isDungeon`-сектор, раз ЛЮБОЙ данж теперь может быть
местом выхода).

**Статус:** не реализовано, реализовывать после подтверждения фикса регистрации.
