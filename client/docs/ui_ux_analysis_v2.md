# UI/UX Анализ v2 — Технический и архитектурный взгляд

Дополнение к `ui_ux_deep_analysis.md`. Фокус на архитектурных решениях, влияющих на UX, производительности UI, навигации и обратной связи.

---

## 1. Архитектурный UX-долг (scene.restart как костыль)

### 1.1. Переключение вкладок через scene.restart()

Во всех модальных сценах (GarageScene:58, MissionsScene:60, CorpScene, InventoryScene) смена таба делает `this.scene.restart()` — полное уничтожение и пересоздание всех display-объектов.

**Проблемы:**
- Потеря состояния скролла — пользователь пролистал список кораблей/предметов, переключил таб, скролл сброшен
- Нет анимации перехода между табами — резкая вспышка перерисовки
- Лишняя работа GC при каждом переключении
- Невозможно сохранить временное состояние (открытый тултип, выделение)

**Решение:**
- Использовать `setVisible()` на контейнерах табов вместо restart
- Либо создать шаблон TabbedScene с lazy-инициализацией панелей

### 1.2. HudScene — 3657 строк монолита

HudScene содержит: миникарту, action bar, чат, панель игрока, панель цели, окно группы, окно друзей, бустеры, кнопки соцсетей, индикатор карго, лог событий, навигацию базы — всю HUD-логику в одном файле.

**Проблемы:**
- `scene.restart()` на resize пересоздаёт абсолютно всё — 3657 строк инициализации при каждом ресайзе
- Сложно тестировать/модифицировать изолированные части
- Состояние групповых окон, чата, лога приходится вручную сохранять через `_logHistory || []` и подобные паттерны

**Решение:**
- Разделение на под-сцены: MinimapScene, ChatScene, ActionBarScene
- Использовать Phaser Containers с управляемой видимостью

## 2. Навигация и информационная архитектура

### 2.1. Неочевидный флоу: количество шагов до цели

Пример: **чтобы экипировать модуль со склада на корабль, игрок должен:**
1. Нажать `I` (InventoryScene)
2. Найти модуль в списке → нажать `УСТАНОВИТЬ`
3. Если модуль в warehouse — сначала открыть CargoScene (другая сцена), переложить в трюм, вернуться в Inventory

**Проблема:** слишком много переключений между сценами для простой операции.

### 2.2. Модальные окна — нет единого стека

Баг: карта (MapScene) может оказаться под nav-баром базы (HudScene._showBaseNav), зафиксировано в коде MapScene:35 `self-bringToTop`.

В проекте нет централизованного управления стеком сцен — каждая сама заботится о своей глубине через `bringToTop`. Это приводит к:
- Окна могут перекрывать друг друга в непредсказуемом порядке
- Нет анимации открытия/закрытия (только резкое появление)
- Нет затемнения фона для модальных окон (каждая сцена рисует свой затемняющий rectangle)

### 2.3. Неединообразные хоткеи закрытия

- GarageScene, InventoryScene, CargoScene, MissionsScene: `ESC`
- SettingsScene: `клик вне панели` + `ESC` (через `scene.stop()`)
- MapScene: не указано, вероятно ESC
- Некоторые сцены показывают `G / ESC` в углу, другие нет

**Проблема:** нет консистентного UX для открытия/закрытия окон. Пользователь должен помнить, какая клавиша что открывает (G — гараж, I — инвентарь, M — карта, K — скиллы, C — корпорации).

## 3. Производительность UI

### 3.1. Canvas в физическом разрешении

```js
const W = () => Math.floor(window.innerWidth * DPR);
const H = () => Math.floor(window.innerHeight * DPR);
```

На 4K-мониторе с DPR=1 (Windows 100%) или DPR=2 (Mac Retina) Canvas может быть 3840×2160. Каждый Phaser Graphics.fillRoundedRect и setText на таком холсте стоит дорого.

### 3.2. UI Scale через camera zoom

```js
this.cameras.main.setZoom(_s.uiScale / 100);
```

**Проблема:** при zoom > 100% всё UI физически рисуется крупнее, но и пикселей занимает больше → больше fill-rate. При zoom < 100% текст становится менее читаемым из-за билинейной интерполяции (несмотря на `pixelArt: false`).

Альтернатива: рендерить UI в отдельный render texture в фиксированном разрешении и скейлить её.

### 3.3. Graphics.clear() + перерисовка каждый кадр

HudScene.update() перерисовывает бары щита/корпуса, полоски цели, миникарту через `Graphics.clear()` + `fillRoundedRect()` каждый кадр. Это десятки draw calls каждый frame.

## 4. Обратная связь и состояния

### 4.1. Нет индикаторов загрузки для операций

В LoginScene при логине кнопка меняет текст на `…` (LoginScene:232), блокируется, но нет спиннера или прогресс-бара. Для save/load через API (особенно при плохом соединении) пользователь видит только "подвисание".

### 4.2. Нет подтверждения деструктивных действий

- Продажа модуля?
- Удаление предмета?
- Выход с арены (кнопка есть, но `_confirmLeaveArena` — нужно проверить, есть ли confirm)

### 4.3. Ошибки: только красный текст

```js
errMsg.textContent = e.message || 'Ошибка сервера';
```

Нет разграничения типов ошибок (network, validation, server). Нет кнопки "повторить". После ошибки логина поля не подсвечиваются.

## 5. Доступность (Accessibility)

### 5.1. Клавиатурная навигация

- Canvas-сцены не поддерживают Tab-навигацию между кнопками
- DOM-оверлей логина поддерживает Tab/Enter (стандартное поведение браузера)
- В игровых сценах вся навигация только через кастомные хоткеи

### 5.2. Цветовая слепота

- Основные цвета: cyan (`#4dd0e1`), amber (`#ffb74d`), emerald (`#66bb6a`), red (`#ef5350`)
- Для дейтеранопии (красно-зелёная) красный и зелёный неразличимы
- Щит (cyan) и красный враги — ок, но `emerald` (корпус) vs `danger` (урон по корпусу) могут сливаться
- Нет паттернов/иконок как дублирующего канала информации

### 5.3. Размер шрифтов

- Минимальный размер: **9px** (хоткеи action bar, HudScene:337) — нечитаем на нативных разрешениях
- 10px — подписи под миникартой, некоторые лейблы вкладок
- WCAG AA требует возможности масштабировать текст до 200% без потери контента

## 6. i18n и интернационализация

### 6.1. Fallback — сырые ключи

```js
if (str === undefined) return key;
```

В проде пользователь видит `ship.argus` вместо названия корабля (упомянуто в ui_ux_deep_analysis.md). Это деградирует UX до нечитаемого состояния.

### 6.2. Только русский язык

- `locales/ru.json` — единственный файл
- Настройка `lang` в settings.js есть (`'ru'` по умолчанию), но переключение не меняет язык — нет загрузчика других локалей
- Код Gamescene не перезагружает локали при смене языка

## 7. Технический UX: DOM vs Phaser

### 7.1. Гибридный рендеринг

- **LoginScene** — полностью DOM-оверлей (HTML-форма)
- **TestProfileScene** — DOM-оверлей
- **SettingsScene** — Phaser-графика (кроме emoji-иконок)
- **HudScene** — Phaser-текст и графика

**Проблема:** DOM-элементы не масштабируются вместе с Phaser-UI при zoom. При uiScale 80% Phaser-текст уменьшается, а DOM-логин-форма остаётся нормального размера.

### 7.2. Emoji вместо иконок

В SettingsScene: `'🎮'`, `'🎨'`, `'🔊'`, `'⌨'`, `'🌐'` для табов. Emoji-рендеринг неконсистентен между платформами (Windows, macOS, Linux) — на Windows некоторые emoji отображаются как монохромные символы.

## 8. Предложения по улучшению

### 🏗 8.1. Scene manager с LIFO-стеком

Создать легковесный слой управления сценами вместо прямых `scene.launch/stop/restart`:
- Единая функция `openModal(key)` — затемняет фон, центрирует, запоминает предыдущую сцену
- `closeModal()` — возврат к предыдущей
- Автоматический bringToTop

### 🔄 8.2. Контейнерные табы вместо restart

Рефакторинг модальных окон с переключением видимости контейнеров:
- Сохраняется скролл, выделение, открытые тултипы
- Анимация fade/slide между табами
- Мгновенное переключение

### ⌨ 8.3. Хоткей-хелпер

Добавить постоянную подсказку внизу экрана:
```
G:Гараж  I:Инвентарь  M:Карта  K:Скиллы  C:Корп  O:Миссии  ESC:Назад
```
Это снижает порог входа для новых игроков.

### 🎯 8.4. Визуальная иерархия для ошибок

Заменить `errMsg.textContent = msg` на:
- Поле подсвечивается красной рамкой (уже есть `borderColor = '#4dd0e1'` при фокусе — сделать и для ошибок)
- Иконка статуса (⚠, ✓) рядом с сообщением
- Кнопка "Повторить" для network-ошибок

### 🎨 8.5. Иконочный шрифт вместо emoji

Заменить emoji в SettingsScene/tabs на кастомный иконочный шрифт или SVG-иконки — консистентный рендеринг на всех платформах.

### ♿ 8.6. Accessibility baseline

- Добавить цветовые паттерны (штриховка/полоски) как альтернативу цвету для баров HP/щита
- Минимальный размер шрифта поднять до 11px
- Tab-навигация хотя бы для основных кнопок (даже через `tabindex` на DOM-оверлеях)

### 📊 8.7. Производительность: offscreen UI

Для HUD-элементов, которые меняются редко (панель игрока, кнопки), использовать `RenderTexture` — один раз отрисовать текстуру и обновлять только при изменении данных, а не каждый кадр.

## Резюме

| Область | Критичность | Влияние на пользователя |
|---|---|---|
| scene.restart() на смену таба | Средняя | Потеря скролла, мигание при переключении |
| Монолитный HudScene | Низкая | Только dev, пользователь не видит |
| Нет стека сцен | Средняя | Окна перекрываются, нет анимации |
| 9px шрифты | Высокая | Нечитаемо на HiDPI |
| Нет подтверждения действий | Средняя | Случайные продажи/удаления |
| Нет индикации загрузки | Средняя | Кажется, что игра зависла |
| i18n fallback (ключи) | Высокая | Видны сырые ключи в проде |
